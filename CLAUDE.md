# Claude Code Configuration

## Project overview

Battle Plan targets Unity 6000.3.1f1 with Netcode for GameObjects for
multiplayer. Match existing patterns rather than introducing new
architecture.

## Unity C# conventions

- No custom namespaces are used anywhere in `Assets/Scripts` — don't add one to a new file, it'll be inconsistent with everything else.
- Networked classes derive from `NetworkBehaviour`. Use `OnNetworkSpawn`/`OnNetworkDespawn` (not `Start`/`Awake`) for setup that depends on network state, and `IsOwner`/`IsServer` to branch ownership logic (see `Assets/Scripts/Units/Unit.cs`).
- RPCs follow `MethodNameServerRpc` / `MethodNameClientRpc` suffix naming with the matching `[ServerRpc]`/`[ClientRpc]` attribute — never call server/client-only logic without going through an RPC.
- Field visibility: use `[SerializeField] private` for fields that only need to be set in the Inspector; use `public` for fields other scripts read/write directly. Both patterns coexist in this codebase — pick based on whether the field is accessed cross-script, don't rewrite existing fields to "fix" this.
- Don't use `GameObject.Find` / `FindObjectOfType` in per-frame code (`Update`, `FixedUpdate`) — cache references (see how `GameLoop`, `NetworkHandler` etc. hold static/serialized refs instead).
- Every asset file (`.cs`, `.prefab`, `.asset`, scenes, models, etc.) has a paired `.meta` file with a stable GUID. When creating, moving, renaming, or deleting an asset, keep its `.meta` file in sync — never hand-edit a GUID inside one.
- Never edit generated/local-only folders: `Library/`, `Temp/`, `obj/`, `UserSettings/`, `Logs/`, `Builds/`. They're gitignored and regenerated by the Editor.
- `GameLoop.cs` is the central, intentionally-monolithic game state/flow controller — prefer adding a method there over creating a new manager class, matching the existing structure.

## Minimize Play-mode time

Running the game slows the user's machine. Treat Play mode as a scarce resource.

**Before entering Play**
- Do all code application and compile iteration OUTSIDE Play mode; reach zero console errors first.
- Run everything that can run in edit mode there instead: pure grid/math assertions via `execute_code`, asset/prefab/scene serialized-value checks, `.asset` stat reads.
- Script the entire runtime session in advance (what to run, what to assert, in what order) so you never idle in Play mode while deciding what to do next.

**While in Play**
- Consolidate runtime verification into as FEW Play sessions as possible — ideally one. Restart matches via `DevInput` inside the session instead of exiting/re-entering Play.
- Keep dev fast-forward high (`DevInput.SetSpeed`) to shorten wall-clock time.
- NEVER edit scripts during Play mode — the domain reload wipes static state and wedges the session. Exit Play → batch ALL pending edits → compile once → re-enter once.
- Stop (or pause via `manage_editor`) before thinking: if you need to analyze results, read files, or plan next steps, exit/pause Play first. Unity must not sit running while you deliberate.

**Knowing when to stop (no fixed waits)**
Never sleep for one long fixed duration and hope the game is done. Instead, poll in a short loop — wait under a second, check, and if not finished wait another second and check again — against observable signals such as:
- `GameLoop.currentPhase` — "planning" / "dodging" / "executing" / "idle" (poll via `execute_code`).
- `DevInput.Dump()` — phase, unit cells/alive, network state, dodge-window membership.
- `DevE2ETest.Report` / `[E2E]` console lines — the suite logs a final `RESULT:` line on completion.
- Prefer self-stopping drivers: a dev-only, editor-guarded hook that sets a done flag / logs a sentinel / calls `UnityEditor.EditorApplication.isPlaying = false` when the last step completes.

**After**
- Exit Play mode as soon as verification concludes; always leave the editor stopped.

## Single Unity Editor coordination

One Unity Editor/MCP instance and one working tree serve all agents. Import,
compilation/domain reload, scene state, tests, builds, and Play mode are
global.

**Editor broker and lease**
- The top-level agent is the editor broker.
- Only the broker, or one explicitly named delegate, may hold the Unity lease.
- The lease covers project-state Unity MCP calls, refresh/import, tests, builds, and Play mode.
- Agents without the lease never call Unity MCP; they request editor work in their handoff.
- Leases are not inherited or sub-delegated. Nested agents default to writer-only.

**Safe parallel work**
- Parallelize filesystem reading, reasoning, review, and edits to disjoint assigned source/docs.
- Give every file one owner; its `.meta` file has the same owner.
- Source writers may trigger partial auto-imports. Treat intermediate console state as transient, never as verification.
- During a lease, other agents may only read, or edit paths outside `Assets/`, `Packages/`, and `ProjectSettings/` that cannot affect the queued verification.

**Work requiring serialization**
- Serialize scene/prefab/GameObject mutation, asset imports, edit/play-mode tests, and builds.
- Do not start a lease while writers can still change Unity-relevant paths.
- Treat compile/domain reload completion as a barrier before reading results.

**Writer handoff** — instead of playtesting, each writer returns:
1. Changed files and expected compile/import impact.
2. Requested edit-mode or serialized-data checks with exact assertions.
3. Runtime setup, steps, observable pass/fail evidence, and completion signal.

**Broker barrier**
1. Wait for all writers, collect handoffs, and close the batch.
2. Freeze writes under `Assets/`, `Packages/`, and `ProjectSettings/`.
3. Refresh/import once; await reload; require zero relevant compile errors.
4. Run queued serialized checks and edit-mode tests.
5. Batch runtime requests into one leased Play session and capture evidence.
6. Stop Unity, then release the freeze and lease.
- Any Unity-relevant write after step 3 begins makes later evidence stale; restart the barrier.

**Locks** — do not rely on a filesystem lock: it cannot gate Unity MCP calls and can become stale. If independent coordinators are unavoidable, a lock is advisory only; one named broker must still grant the lease and recover abandoned ownership.
